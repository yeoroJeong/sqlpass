NULL 비교와 UNKNOWN

SQL에서 NULL은 값이 없거나 알려지지 않았음을 나타냅니다. 일반 비교의 결과는 TRUE · FALSE · UNKNOWN 중 하나입니다. 아래 Oracle SQL 예제에서 같은 점수 조건을 어디에 두는지에 따라 달라지는 결과를 확인할 수 있습니다.

비교와 3값 논리

일반 비교와 IS NULL

SELECT s.student_name, r.score,
  CASE WHEN (r.score >= 60) THEN 'TRUE'
       WHEN NOT (r.score >= 60) THEN 'FALSE'
       ELSE 'UNKNOWN' END AS at_least_60,
  CASE WHEN (r.score = NULL) THEN 'TRUE'
       WHEN NOT (r.score = NULL) THEN 'FALSE'
       ELSE 'UNKNOWN' END AS eq_null,
  CASE WHEN (r.score <> NULL) THEN 'TRUE'
       WHEN NOT (r.score <> NULL) THEN 'FALSE'
       ELSE 'UNKNOWN' END AS ne_null,
  CASE WHEN (r.score IS NULL) THEN 'TRUE'
       WHEN NOT (r.score IS NULL) THEN 'FALSE'
       ELSE 'UNKNOWN' END AS is_null,
  CASE WHEN (r.score IS NOT NULL) THEN 'TRUE'
       WHEN NOT (r.score IS NOT NULL) THEN 'FALSE'
       ELSE 'UNKNOWN' END AS is_not_null
FROM student s JOIN score_result r ON s.id = r.student_id
ORDER BY s.id;

일반 비교 연산자 (=, <>, <, >, <=, >=)는 피연산자 중 하나라도 NULL이면 UNKNOWN을 반환합니다. NULL = NULL도 UNKNOWN입니다. NULL 여부는 IS NULL 또는 IS NOT NULL로 판정합니다.

AND · OR · NOT

SELECT
  CASE WHEN (NULL = 1 AND 1 = 0) THEN 'TRUE'
       WHEN NOT (NULL = 1 AND 1 = 0) THEN 'FALSE'
       ELSE 'UNKNOWN' END AS and_result,
  CASE WHEN (NULL = 1 OR 1 = 1) THEN 'TRUE'
       WHEN NOT (NULL = 1 OR 1 = 1) THEN 'FALSE'
       ELSE 'UNKNOWN' END AS or_result,
  CASE WHEN (NOT (NULL = 1)) THEN 'TRUE'
       WHEN NOT (NOT (NULL = 1)) THEN 'FALSE'
       ELSE 'UNKNOWN' END AS not_result
FROM dual;

조건을 쓰는 위치

WHERE · TRUE인 행만 조회

SELECT student_id, score
FROM score_result
WHERE score >= 60
ORDER BY student_id;
STUDENT_IDSCORE
180

영희(40)는 FALSE, 민수(NULL)는 UNKNOWN이라 둘 다 제외됩니다.

HAVING · TRUE인 그룹만 조회

SELECT student_id, AVG(score) AS avg_score
FROM score_result
GROUP BY student_id
HAVING AVG(score) >= 60
ORDER BY student_id;
STUDENT_IDAVG_SCORE
180

민수 그룹은 점수가 모두 NULL이라 AVG(score)도 NULL입니다. 따라서 HAVING 조건은 UNKNOWN이고 그룹이 제외됩니다.

INNER JOIN · TRUE인 조합만 매칭

SELECT s.student_name, r.student_id AS matched_id, r.score
FROM student s
INNER JOIN score_result r
  ON s.id = r.student_id AND r.score >= 60
ORDER BY s.id;
STUDENT_NAMEMATCHED_IDSCORE
지수180

민수는 ID가 같아도 점수 조건이 UNKNOWN입니다. ON 전체가 TRUE여야 매칭됩니다.

LEFT JOIN · 매칭이 없어도 왼쪽 행 보존

SELECT s.student_name, r.student_id AS matched_id, r.score
FROM student s
LEFT JOIN score_result r
  ON s.id = r.student_id AND r.score >= 60
ORDER BY s.id;
STUDENT_NAMEMATCHED_IDSCORE
지수180
영희NULLNULL
민수NULLNULL

영희는 FALSE, 민수는 UNKNOWN으로 매칭이 실패합니다. 두 학생 행은 남고 오른쪽 컬럼은 모두 NULL로 채워집니다. MATCHED_ID를 보면 원래 점수 행이 매칭됐는지 알 수 있습니다.

LEFT JOIN 뒤 WHERE · 조인 결과를 필터링

SELECT s.student_name, r.student_id AS matched_id, r.score
FROM student s
LEFT JOIN score_result r ON s.id = r.student_id
WHERE r.score >= 60
ORDER BY s.id;
STUDENT_NAMEMATCHED_IDSCORE
지수180

이번에는 세 학생의 ID가 모두 매칭되지만, WHERE에서 영희의 40과 민수의 NULL이 걸러집니다.

CHECK · FALSE만 저장 거부

CREATE TABLE score_check_example (
  id NUMBER PRIMARY KEY,

CASE WHEN · TRUE인 분기의 값 반환

SELECT s.student_name, r.score,
  CASE WHEN r.score >= 60 THEN '합격'
       ELSE '미충족' END AS simple_status,
  CASE WHEN r.score IS NULL THEN '미응시'
       WHEN r.score >= 60 THEN '합격'
       ELSE '불합격' END AS detailed_status
FROM student s JOIN score_result r ON s.id = r.student_id
ORDER BY s.id;

UNKNOWN인 WHEN은 건너뜁니다. 참인 WHEN이 없으면 ELSE를 사용하고, ELSE도 없으면 NULL을 반환합니다.

NOT IN 기출 · COUNT(*)는 0

SELECT COUNT(*) AS row_count
FROM tab_a
WHERE col1 NOT IN (SELECT col1 FROM tab_b);
ROW_COUNT
0

NOT IN (1, NULL)은 x <> 1 AND x <> NULL로 계산합니다.

IN · 일치 하나면 TRUE

SELECT col1
FROM tab_a
WHERE col1 IN (SELECT col1 FROM tab_b)
ORDER BY col1;
COL1
1

IN (1, NULL)은 x = 1 OR x = NULL로 계산합니다. 1은 TRUE OR UNKNOWN이라 남고, 2와 3은 UNKNOWN이라 제외됩니다.

NOT EXISTS · 같은 값을 가진 행이 있는지 검사

SELECT a.col1
FROM tab_a a
WHERE NOT EXISTS (
  SELECT 1 FROM tab_b b WHERE b.col1 = a.col1
)
ORDER BY a.col1;
COL1
2
3

TAB_B의 NULL은 안쪽 WHERE에서 매칭되지 않습니다. 이 예제에 TAB_A의 NULL을 추가하면 그 행도 반환됩니다. 제외하려면 바깥 WHERE에 a.col1 IS NOT NULL을 추가합니다.

NOT IN · 오른쪽 NULL을 명시적으로 제외

SELECT col1
FROM tab_a
WHERE col1 NOT IN (SELECT col1 FROM tab_b WHERE col1 IS NOT NULL)
ORDER BY col1;
