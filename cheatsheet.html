1. 데이터 모델링

ERD를 읽는 순서

  1. 엔터티에서 관리하는 대상을 찾고 속성과 인스턴스를 구분합니다.
  2. 관계 양쪽의 최소·최대 참여 수를 각각 읽습니다. 고객에게 주문은 0건 이상일 수 있고, 주문마다 고객이 한 명일 수 있습니다.
  3. 부모의 키가 자식의 PK에도 들어가는지 확인합니다. 주문상세(주문ID, 상품ID)에서 주문ID가 PK의 일부라면 주문과 주문상세는 식별관계입니다.

2. Oracle SQL 기초

SELECT, DUAL, 리터럴과 별칭

Oracle 19c에서도 실행할 수 있는 예제입니다. 테이블 없이 식을 계산할 때 한 행을 가진 DUAL을 사용합니다. 문자열은 작은따옴표, 대소문자나 공백을 보존할 별칭은 큰따옴표로 감쌉니다.

SELECT 2 + 3 AS total, 'SQL' || 'D' AS "시험 이름",
       DATE '2026-11-01' AS first_day
FROM dual;
-- TOTAL = 5, 시험 이름 = SQLD, FIRST_DAY = 2026-11-01 자정

처리 순서는 FROM·JOIN → WHERE → GROUP BY → HAVING → SELECT → ORDER BY입니다. Oracle 19c에서는 같은 쿼리 블록의 SELECT 별칭을 ORDER BY에서 사용할 수 있습니다.

자료형과 날짜 변환

NUMBER(p,s)는 전체 유효 자릿수와 소수 자릿수를 지정합니다. CHAR는 고정 길이, VARCHAR2는 가변 길이입니다. DATE에는 시·분·초까지 저장되며 TIMESTAMP는 초의 소수부를 저장할 수 있습니다.

SELECT TO_DATE('2026-11-11 13:30', 'YYYY-MM-DD HH24:MI') AS at_time,
       TO_CHAR(DATE '2026-11-11', 'YYYY/MM/DD') AS label,
       DATE '2026-11-11' + 1 AS next_day,
       TO_NUMBER('42') AS amount
FROM dual;

TO_DATE는 문자열 → 날짜, TO_CHAR는 날짜나 숫자 → 문자열입니다. 날짜 조건에는 created_at >= DATE '2026-11-01' AND created_at < DATE '2026-12-01'처럼 끝 경계를 제외하면 시간값이 있는 월말 행도 포함됩니다.

NULL, 문자열·숫자 함수, CASE

NULL 비교 예제와 실행 결과 보기 →

Oracle에서 길이 0의 문자열은 NULL로 처리합니다. NULL 비교에는 IS NULL을 쓰고, 대체값은 NVL 또는 COALESCE를 사용합니다. NULLIF(a,b)는 두 값이 같을 때 NULL을 반환합니다.

SELECT NVL(NULL, 0) AS n, SUBSTR('ORACLE', 2, 3) AS part,
       ROUND(15.67, 1) AS rounded, TRUNC(15.67, 1) AS cut,
       CASE WHEN 70 >= 60 THEN 'PASS' ELSE 'RETRY' END AS result
FROM dual;
-- 0, RAC, 15.7, 15.6, PASS

NVL2(x,a,b)는 x에 값이 있으면 a, NULL이면 b를 반환합니다. DECODE는 값별 분기에, CASE는 범위 조건을 포함한 분기에 사용할 수 있습니다.

LIKE에서 %는 0글자 이상, _는 한 글자입니다. Oracle의 ORDER BY 기본 NULL 위치는 ASC에서 뒤, DESC에서 앞입니다. NULLS FIRST 또는 NULLS LAST로 지정할 수 있습니다.

조인과 집계로 결과 행 세기

LEFT JOIN은 왼쪽 행을 보존합니다. 오른쪽 필터를 ON에 두면 매칭만 제한하고, WHERE에서 오른쪽 NULL 확장행을 걸러내면 왼쪽 고객도 사라질 수 있습니다.

WITH customers AS (
  SELECT 1 AS id FROM dual UNION ALL SELECT 2 FROM dual
), payments AS (
  SELECT 1 AS customer_id, 80 AS amount FROM dual
)
SELECT c.id, COUNT(*) AS joined_rows, COUNT(p.amount) AS paid
FROM customers c
LEFT JOIN payments p ON p.customer_id = c.id AND p.amount >= 50
GROUP BY c.id
ORDER BY c.id;
-- ID 1: joined_rows 1, paid 1 / ID 2: joined_rows 1, paid 0

3. SQL 활용과 결과 예측

서브쿼리, 집합 연산과 소계

  • 단일행 서브쿼리에 0행이 나오면 스칼라 값은 NULL, 2행 이상이면 오류가 납니다. 여러 행과 비교하려면 IN, ANY, ALL 등을 검토합니다.
  • NOT IN에 NULL이 섞이면 비교가 UNKNOWN이 될 수 있습니다. 매칭 행의 부재는 상관 조건을 건 NOT EXISTS로 검사할 수 있습니다.
  • UNION은 중복 제거, UNION ALL은 유지, INTERSECT는 교집합, Oracle의 MINUS는 왼쪽 차집합입니다.
  • ROLLUP(a,b)는 (a,b), (a), ()를 만들고 CUBE는 (b)도 포함합니다. GROUPING SETS는 원하는 집계 조합을 지정합니다. GROUPING으로 소계가 만든 NULL을 구분합니다.

윈도우 프레임과 그룹별 Top N

GROUP BY는 그룹별로 행을 합칩니다. 윈도우 함수는 각 결과 행에 순위나 합계를 붙입니다. 점수 90·90·80의 RANK는 1·1·3, DENSE_RANK는 1·1·2입니다.

WITH scores AS (
  SELECT 1 AS id, 90 AS score FROM dual UNION ALL
  SELECT 2, 90 FROM dual UNION ALL SELECT 3, 80 FROM dual
)
SELECT id, score, RANK() OVER (ORDER BY score DESC) AS rnk,
       SUM(score) OVER (ORDER BY score DESC, id
         ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW) AS total
FROM scores
ORDER BY score DESC, id;
-- 순위 1, 1, 3 / 누적합 90, 180, 260

ROWS는 행 위치, RANGE는 정렬값 기준입니다. LAST_VALUE는 현재 프레임의 끝을 읽습니다. 전체 파티션의 끝이 필요하면 프레임 끝을 UNBOUNDED FOLLOWING으로 지정합니다.

그룹별 Top N은 안쪽 쿼리에서 ROW_NUMBER나 DENSE_RANK를 계산하고 바깥 WHERE에서 필터링합니다. 전체 Top N은 ORDER BY score DESC FETCH FIRST 3 ROWS ONLY로 구할 수 있습니다. ROWNUM 방식은 안쪽 쿼리에서 먼저 정렬하고 바깥에서 ROWNUM <= 3을 적용하세요. 같은 블록에서 먼저 ROWNUM으로 자르면 정렬 후의 상위 3행과 달라질 수 있습니다. RANGE 연습

Oracle 계층형 질의, PIVOT, 정규식

WITH org AS (
  SELECT 1 AS id, CAST(NULL AS NUMBER) AS parent_id FROM dual
  UNION ALL SELECT 2, 1 FROM dual
)
SELECT id, LEVEL AS depth
FROM org
START WITH parent_id IS NULL
CONNECT BY PRIOR id = parent_id;
-- (1, 1), (2, 2)

PRIOR가 붙은 식은 부모 행에서 평가합니다. START WITH는 루트를 정하고 ORDER SIBLINGS BY는 형제끼리 정렬합니다.

PIVOT은 범주를 열로 펼치며 집계합니다. UNPIVOT은 여러 열을 행으로 바꿉니다. REGEXP_LIKE(code, '^[0-9]+$')는 한 글자 이상의 숫자로만 이뤄진 값을 찾습니다.

4. 관리 구문과 트랜잭션

DDL, DML, DCL과 제약조건

CREATE·ALTER·DROP·TRUNCATE는 구조를 다루는 DDL입니다. INSERT·UPDATE·DELETE·MERGE는 데이터 변경, GRANT·REVOKE는 권한 관리에 씁니다. PK는 유일성과 비NULL을, FK는 참조 무결성을 보장합니다. FK의 NULL 허용 여부는 별도 NOT NULL 조건을 확인합니다.

CREATE TABLE study_note (
  id NUMBER(6) PRIMARY KEY,
  title VARCHAR2(80 CHAR) NOT NULL,
  created_at DATE DEFAULT SYSDATE
);

INSERT INTO study_note (id, title) VALUES (1, 'JOIN');
UPDATE study_note SET title = 'LEFT JOIN' WHERE id = 1;
COMMIT;

실습 스키마에 테이블을 만든 뒤 실행하는 예제입니다. UPDATE나 DELETE의 WHERE를 생략하면 전체 행이 대상입니다.

Oracle 저장점과 SQL Server 중첩 비교

-- 위 study_note 예제를 실행한 상태에서 실행
UPDATE study_note SET title = '집계' WHERE id = 1;
SAVEPOINT before_window;
UPDATE study_note SET title = '윈도우' WHERE id = 1;
ROLLBACK TO before_window;
COMMIT;
-- 확정된 제목: 집계

Oracle에서 유효한 DDL 실행 전에는 암묵적 커밋이 발생하고, 성공한 DDL 뒤에도 커밋이 발생합니다. 이전 DML의 롤백 가능 여부를 판단할 때 DDL의 위치를 확인하세요.

SQL Server에서는 중첩 BEGIN이 @@TRANCOUNT를 늘리고 안쪽 COMMIT은 횟수만 줄입니다. 저장점 없는 ROLLBACK은 열린 범위 전체를 취소합니다. 교재 Ⅱ-123번 · 저장점 연습
